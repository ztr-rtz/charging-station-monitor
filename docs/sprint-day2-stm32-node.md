## 2. SHT30 软件 I2C（PB6/PB7）

**为什么软件 I2C**：F103 硬件 I2C 有官方 errata（总线卡死/事件异常），业界普遍避开；
GPIO 模拟 100kHz 标准模式，稳定可控。**这是面试点，要能讲。**

### 关键参数
| 项 | 值 |
|---|---|
| 从机地址 | 0x44（7 位）→ 写 0x88 / 读 0x89 |
| 测量命令 | **0x2C 0x06**（周期测量，高重复性） |
| 读取 | 发送命令后延时 ≥15ms → 读 6 字节 |
| 数据格式 | 温度高字节 + 低字节 + CRC8 + 湿度高字节 + 低字节 + CRC8 |

### 换算公式（写死）
```
温度(℃) = -45 + 175 × raw/65535     # raw = 16bit 无符号
湿度(%RH) = 100 × raw/65535
```

### 实现顺序（按这个写，别跳）
1. I2C 起始/停止/读写位时序（delay 用 nop 循环微调，100kHz → 半周期 5μs @72MHz）
2. 写命令 → 读 6 字节
3. **CRC8 校验**（多项式 0x31，初值 0xFF）——校验失败丢弃本轮
4. 换算 → 存 40001/40002
5. 采集间隔 500ms（SHT30 转换只要 4~15ms，比 DHT11 的 1s 强太多）

### 坑
- 软件 I2C 的 SDA 方向切换：读 1 字节时先写 1（释放），再切输入
- 时序参数记到注释里（5μs/位），联调时好调
- 若 SHT30 没到货 → 先用 DHT11 顶（node-design.md 有方案），寄存器契约不变

## 3. ADC 多通道 + DMA（PA0/PA1/PA2）

### 配置要点
| 项 | 值 |
|---|---|
| ADC1 | 规则组：CH0/CH1/CH2 三通道 |
| 模式 | 扫描 + 连续转换，**DMA 循环搬运**（不占 CPU） |
| 采样时间 | 拉长到 **239.5 周期**（信号源阻抗高，采样不足值会偏） |
| 缓冲区 | 每通道 16 次采样数组，软件取平均后换算 |

### 换算公式（写死，标定参数）
```
电压(V) = ADC_val/4096 × 3.3 × 分压比     # 分压比如 30k/(30k+10k)=1.333 → 补实际值
电流(A) = (ADC_val/4096 × 3.3 - V_offset) / 灵敏度   # ACS712-20A：V_offset=2.5V，灵敏度 100mV/A
烟雾    = ADC_val（原始值，阈值判在网关）
```
> 分压比/偏置标定表：node-design.md §6 有，先在代码里写近似值，Day 4 联调再校。

### 坑
- **ACS712 输出范围 0~5V，必须分压/偏置到 3.3V 量程再进 PA2**，否则烧引脚（node-design.md 强调过）
- MQ-2 上电**预热 60s** 再取数，预热期烟雾值标记无效
- DMA 缓冲区用 volatile 数组，主循环读时要防撕裂（简单方法：关 DMA 拷贝或双缓冲）

## 4. Modbus 从站（USART1 + PA8）

### 寄存器区（契约，不许改）
| 寄存器地址(0x) | Modbus 地址 | 内容 | 类型 |
|---|---|---|---|
| 0x0000 | 40001 | 温度 | int16 ×10（0.1℃） |
| 0x0001 | 40002 | 湿度 | uint16 ×10（0.1%RH） |
| 0x0002 | 40003 | 烟雾 | uint16（ADC 原始值） |
| 0x0003 | 40004 | 电压 | uint16 ×10（0.1V） |
| 0x0004 | 40005 | 电流 | int16 ×100（0.01A） |
| 0x0005 | 40006 | 预留 | 0 |
| 0x0006 | 40007 | 预留 | 0 |
| 0x0007 | 40008 | 状态字 | uint16（bit 定义见下） |

**40008 状态字 bit 定义**：bit0 传感器故障 ｜ bit1 温度越限 ｜ bit2 湿度越限 ｜ bit3 烟雾越限 ｜ bit4 电压越限 ｜ bit5 电流越限
（节点只置位"本地粗判"，主判权在网关——薄节点厚网关）

### 请求帧解析（功能码 03 只做这一个）
```
主机 → : [从站地址 1B][功能码 03][寄存器起始 2B][数量 2B][CRC16 2B]  = 8 字节
从机 ← : [地址 1B][功能码 03][字节数 1B][数据 N×2B][CRC16 2B]        = 3+2N 字节
```

### 实现顺序
1. CRC16（MODBUS 多项式 0xA001，查表法）——**先写这个，用测试向量验证**
   - 测试向量：`01 03 00 00 00 08` → CRC = `0x45 C6`（低字节在前）
   - 不会算的话网上有现成查表，抄过来先测对
2. USART1 接收中断 → 攒到 8 字节（或空闲中断判断帧尾）→ 校验地址 + CRC
3. 地址匹配才应答；不匹配直接丢弃（多节点共存的基础）
4. 组响应帧 → **PA8 拉高（发送态）→ 延时 ~50μs → 发数据 → 发完等帧发完 → 拉低（接收态）**
5. 帧间间隔 ≥ 3.5 字符时间（9600 → 约 4ms），响应不要太快，符合 Modbus 规范

### 异常响应（面试加分，顺手做）
- 数量超范围 → 返回 `01 83 02 CRC`（非法数据地址）
- 功能码不支持 → 返回 `01 81 01 CRC`

### 坑
- **PA8 方向切换的时机**：必须"先拉高再发、发完再拉低"，且收发切换留延时——半双工时序错了，数据会丢第一个/最后一个字节，这是 RS485 最常见 bug
- 响应帧发送用阻塞方式（HAL_UART_Transmit），接收用中断，互不干扰
- 寄存器值更新（主循环）和应答读取（中断）共享数组 → 简单做法：应答时**一次性把 16 字节拷出来再组帧**，别边读边拼

## 5. 主循环结构（500ms 周期）

```
while(1):
    if (500ms 到):
        SHT30 读温湿度 → 校验 → 存 40001/40002
        ADC 读三通道 → 平均 → 换算 → 存 40003/40004/40005
        更新 40008 状态字（本地粗判）
    # Modbus 应答由 USART 中断完成，主循环不阻塞
```

## 6. 调试链路（今日验证）

```
电脑串口助手 / ModbusPoll
      │ USB-TTL
      ▼
   MAX485(A/B) ──┐
                 ├── 120Ω 终端电阻（两端各一个）
   STM32 MAX485(A/B) ──┘
```

1. 先用串口助手手动发 `01 03 00 00 00 08` + CRC（`45 C6`），看能不能收到 19 字节
2. 通了之后上 ModbusPoll（设置：9600/8N1/从站 1/功能码 03/起始 40001/数量 8）
3. 用手捏 SHT30（升温）、晃动 MQ-2 模块（冒烟测试用打火机气体/酒精棉，注意别烤到）——看寄存器值变化
4. **数值不合理先查换算公式和分压比，别怀疑协议**
