# 充电站环境检测系统 —— 项目框架与实施计划

> 版本 v0.3 ｜ 2026-08-17 ｜ 用途：秋招简历项目（嵌入式 / 物联网方向）
> 本文档只定义**框架与计划**，不包含具体代码实现。
> v0.3 新增：双链路（RS485 有线 + nRF24L01 无线）组网设计与 Linux 驱动能力规划（§6.3）。

## 1. 项目定位

**分布式充电站环境检测系统**：用多块 STM32F103 作为采集节点，感知充电站环境变量（温湿度、烟雾/可燃气体、电压电流）；用一块 i.MX6ULL（正点原子 MINI）作为边缘网关，完成数据汇聚、边缘处理与本地可视化，再通过 MQTT 上报 OneNET 云平台，实现远程监控与告警。

一句话总结（简历可写）：
> 基于「STM32 采集节点 + i.MX6ULL 边缘网关 + OneNET 云平台」的三层分布式物联网系统，打通 RS485/Modbus 工业总线与 MQTT 云上链路，实现多节点环境数据采集、边缘告警、本地 LVGL 可视化与云端监控。

## 2. 系统架构

### 2.1 三层拓扑

```
┌──────────────────────────────────────────────────────────────┐
│  应用层 · 云端 OneNET Studio                                  │
│  设备管理 · 物模型属性存储 · 数据曲线 · 告警推送 · 远程查看      │
└──────────────────────────▲───────────────────────────────────┘
                           │ MQTT over TCP :1883 · QoS1 · 物模型属性上报
┌──────────────────────────┴───────────────────────────────────┐
│  汇聚层 · i.MX6ULL 网关（正点原子 MINI · Cortex-A7 · Linux）    │
│  数据汇聚 ─ 边缘处理（滤波/阈值/告警）─ 本地展示（LVGL 800×480）  │
└──────────────────────────▲───────────────────────────────────┘
                           │ RS485 总线 · Modbus RTU（9600 8N1 · 从站 1~N）── 有线主线
                           │ nRF24L01 · 2.4GHz · Modbus 帧透传（32B 单包）── 无线扩展
┌──────────────────────────┴───────────────────────────────────┐
│  感知层 · STM32F103 采集节点 × N（RS485 节点 1~2 + 无线节点 3）  │
│  DHT11(单总线) · MQ-2(ADC) · 电压电流采样(ADC) · Modbus 从站    │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 网关软件框架（单进程多线程）

| 域 | 线程 | 职责 |
|---|---|---|
| 采集域 | 采集线程 | 采集通道抽象层（RS485 / nRF24L01 双链路）+ Modbus RTU 主站：帧组装/CRC16/轮询调度/超时重试 |
| 处理域 | 处理线程 | 消费采集队列：环形缓冲 → 滤波/量程换算 → 阈值告警状态机 |
| 存储 | （处理线程写 / MQTT 线程读） | SQLite 本地缓存：断网补传、历史查询、数据落盘防丢失 |
| 展示 | UI 线程 | LVGL 800×480 @60Hz：实时仪表盘、历史曲线、告警页 |
| 上报 | MQTT 线程 | paho-mqtt-c：OneNET 物模型 JSON 上报、心跳、断线重连 |

数据流：
```
传感器 → Modbus 寄存器 → RS485 → 串口 → Modbus 主站解析
→ 原始数据 → 滤波/换算 → 归一化数据
   ├─→ LVGL 界面显示
   ├─→ SQLite 缓存（联网后补传）
   └─→ MQTT 上报 OneNET
```

关键点：模块间用**队列 + 互斥锁**解耦，采集/处理/UI/上报互不阻塞；告警在边缘侧判定，云上只收结果——这是「边缘计算」的体现，面试高频话题。

## 3. 关键技术选型（含理由，简历面试素材）

| 环节 | 选型 | 理由 / 面试价值 |
|---|---|---|
| 节点↔网关 | RS485 + Modbus RTU | 工业总线经典组合，多节点轮询，抗干扰、传输距离远；体现「现场总线」概念 |
| 节点↔网关（无线扩展） | nRF24L01 + 2.4GHz | 通道抽象层统一双链路；Modbus 帧压缩进 32B 单包、协议栈跨物理层复用；SPI 外设做成内核驱动（§6.3） |

| 边缘处理 | 滑动平均滤波 + 阈值告警状态机 | 体现「边缘计算」思路：本地降噪、本地判警，减少云上流量 |
| 本地展示 | LVGL + Linux framebuffer | GUI 库移植与事件驱动 UI，800×480 @60Hz，`lv_timer` 周期性刷新 |
| 上云链路 | MQTT（paho-mqtt-c）+ OneNET 物模型 | 物联网通信主流协议；QoS1、心跳保活、断线重连、离线补传 |
| 数据缓存 | SQLite | 嵌入式数据库，断网不丢数据，联网补传 |
| 系统集成 | CMake 交叉编译 + systemd + 看门狗 | 完整 Linux 应用工程化能力 |

## 4. 协议设计（先行定义，避免返工）

### 4.1 Modbus RTU 寄存器映射（节点侧）

| 寄存器地址 | 含义 | 类型/单位 | 说明 |
|---|---|---|---|
| 40001 | 温度 | int16 × 10（0.1℃） | DHT11 |
| 40002 | 湿度 | uint16 × 10（0.1%RH） | DHT11 |
| 40003 | 烟雾浓度 | uint16（ADC 原始值或 ppm） | MQ-2 |
| 40004~40005 | 电压 | uint32 × 100（0.01V） | 双寄存器（32 位大端） |
| 40006~40007 | 电流 | uint32 × 1000（0.001A） | 双寄存器 |
| 40008 | 节点状态字 | bit 位 | 传感器故障、越限告警等 |

> 功能码固定用 **0x03（读保持寄存器）**；从站地址 1~N；波特率 9600-8-N-1。
> 映射表是「主从双方」的契约，先定死再写代码，面试时能讲清楚「协议先行的工程方法」。

### 4.2 MQTT（OneNET Studio 物模型）

- Broker：`mqtt.heclouds.com:1883`
- 鉴权：ClientID = 设备名，Username = 产品 ID，Password = 设备密钥
- 上报 Topic：`$sys/{产品ID}/{设备名}/thing/property/post`
- 报文示例：
```json
{
  "id": "20260817183000123",
  "version": "1.0",
  "params": {
    "temperature": { "value": 25.3 },
    "humidity":    { "value": 56.8 },
    "smoke":       { "value": 12 },
    "voltage":     { "value": 220.1 },
    "current":     { "value": 3.2 },
    "alarm":       { "value": 0 }
  }
}
```

## 6. 秋招简历价值点与面试准备

### 6.1 简历可写的能力标签

- 多协议通信：UART / RS485 / Modbus RTU / MQTT / 单总线(DHT11) / ADC / SPI(nRF24L01)
- 分布式架构：多节点采集 → 边缘网关 → 云平台三层解耦；RS485 + nRF24L01 双链路组网
- Linux 驱动开发：字符设备、SPI 驱动框架、设备树、GPIO 中断与底半部（详见 §6.3）
- 多线程与同步：生产者-消费者、互斥锁、队列解耦
- 状态机：Modbus 轮询调度、断线重连、告警状态机
- 边缘计算：本地滤波与阈值判警，降低云端压力
- 工程化：CMake 交叉编译、SQLite、systemd、看门狗

### 6.2 高频面试题预案

1. **为什么节点间用 Modbus RTU 而不是自定义协议？** → 工业标准、兼容性好、CRC 校验、寄存器语义清晰
2. **QoS0/1/2 的区别？为什么用 QoS1？** → 至少一次 vs 最多一次 vs 恰好一次，QoS1 平衡可靠性与开销
3. **断网了数据怎么办？** → SQLite 本地缓存 + 重连补传
4. **RS485 是多主还是单主？冲突怎么办？** → 单主多从、轮询，从站只在被询时应答
5. **LVGL 刷新机制？** → `lv_timer_handler` 周期调用，脏矩形重绘，60Hz 由帧率控制
6. **多线程之间怎么共享数据？** → 队列 + 互斥锁，避免竞态

### 6.3 Linux 驱动能力体现（本项目如何展示驱动）

> 项目主线是应用层，但通过三个「驱动工作点」把 Linux 驱动开发能力真正写进简历——不是为驱动而驱动，而是驱动功能直接服务于产品功能（无线链路、状态指示、UI 交互）。

**① 设备树与外设 bring-up（阶段 0，地基）**
- 梳理 / 修改 i.MX6ULL 设备树：调试串口、SPI1 控制器、GPIO 复用（RS485 方向控制脚、nRF24L01 片选/IRQ）
- 体现：读得懂 DTS、能配置 pinmux、能确认内核设备注册是否成功
- 产出：`docs/device-tree.md`，逐个外设记录设备树节点与对应内核驱动

**② nRF24L01 内核 SPI 驱动（阶段 1~2，最高含金量）**
- 不依赖用户态 spidev，自己写字符设备驱动（spi_driver 注册）
- 覆盖内核机制：
  - SPI 传输：`spi_sync` / `spi_transfer`（片选、速率、位序）
  - GPIO 中断注册 + 底半部：IRQ 触发接收，workqueue 处理数据
  - 并发保护：mutex / spinlock，read/write 的睡眠与原子路径
  - `file_operations`：open / read / write / ioctl（读数据、配置信道与速率）
- 用户态接口：应用层 `read()` 拿数据、`ioctl()` 配置，完全不感知内核细节
- 产出：`gateway/driver/nrf24l01/` 驱动源码 + Makefile + 加载说明
- 面试脚本：insmod 加载流程 → 设备树匹配 → 中断处理 → 与应用层的数据通路

**③ LED / 按键字符驱动（阶段 2，量小见效快）**
- LED 做成 miscdevice 字符设备：`write()` 控制状态灯（链路在线 / 离线 / 告警），驱动功能直接服务产品
- 按键走 input 子系统 + GPIO 中断：切换 LVGL 页面 / 确认告警，形成「驱动 → 应用」完整闭环
- 产出：驱动与 LVGL 应用联动演示

**分层呈现结构（简历 / 讲稿骨架）**
```
应用层：LVGL / MQTT / 采集调度（用户态）
驱动层：nrf24l01 字符驱动 / led / 按键（内核态，insmod 加载）
内核  ：设备树 / SPI 框架 / 中断与底半部 / 并发原语
```

**简历 bullet 参考**
> 基于 i.MX6ULL 实现 nRF24L01 内核 SPI 字符设备驱动（设备树匹配、SPI 传输、GPIO 中断与底半部、并发保护），封装为统一采集通道，与 RS485/Modbus 有线链路组成双链路分布式采集系统。

## 7. 风险与注意事项

| 风险 | 对策 |
|---|---|
| LVGL 依赖编译链复杂（字体/触摸驱动） | 先用 framebuffer + 鼠标/键盘调试，再适配触摸 |
| RS485 方向切换时序（DE/RE） | 收发切换用 GPIO 控制，预留 T1 延时 |
| 正点原子 MINI 屏幕与 LVGL 驱动匹配 | 确认内核 framebuffer 设备号与像素格式（RGB565/ARGB8888） |
| OneNET 鉴权信息（产品ID/设备密钥） | 配置文件集中管理，不入库不入代码 |
| 时间预算超支 | 阶段里程碑先行，先打通链路再优化细节 |
