## 1. 项目一句话

**分布式充电站环境检测系统**：多块 STM32F103 采集节点感知充电站环境（温湿度/烟雾/电压电流），经 RS485/Modbus 有线主线 + nRF24L01 无线扩展双链路汇聚至 i.MX6ULL 边缘网关；网关完成数据滤波、阈值告警、LVGL 本地可视化与 SQLite 断网缓存，通过 MQTT 上报 OneNET 云平台，实现远程监控与告警。

> 简历版一句话：
> 基于「STM32 采集节点 + i.MX6ULL 边缘网关 + OneNET 云平台」的三层分布式物联网系统，打通 RS485/Modbus 工业总线、nRF24L01 无线链路与 MQTT 云上链路，实现多节点环境数据采集、边缘告警、本地 LVGL 可视化与云端监控。

## 2. 系统架构（三层）

```
┌───────────────────────────────────────────────────────────────┐
│ 应用层 · OneNET Studio（物模型属性 · 数据曲线 · 告警推送）         │
│              ▲ MQTT over TCP:1883 · QoS1 · 断线重连 · 离线补传    │
┌──────────────┴───────────────────────────────────────────────┐
│ 汇聚层 · i.MX6ULL 网关（正点原子 MINI · Cortex-A7 · Linux）      │
│  采集通道抽象层(RS485/nRF24L01) → 边缘处理(滤波/阈值/告警)        │
│  → SQLite 断网缓存 → LVGL 800×480 本地展示 → MQTT 上报            │
│              ▲ RS485 总线(有线主线) ／ 2.4GHz(无线扩展)           │
┌──────────────┴───────────────────────────────────────────────┐
│ 感知层 · STM32F103 节点 × N（Modbus 从站 · 薄节点架构）           │
│  SHT30(I2C) 温湿度 · MQ-2(ADC) 烟雾 · 电压电流(ADC) · 蜂鸣器告警   │
└───────────────────────────────────────────────────────────────┘
```

**核心架构决策：**
- **薄节点、厚网关**：节点只做采集+硬保护，滤波/告警/存储/上报全在网关边缘侧——算力匹配、参数统一管理、支持热更新、原始数据可溯源
- **单进程多线程**（网关）：采集/处理/UI/MQTT 四线程 + 队列/互斥锁解耦，生产者-消费者模型
- **通道抽象层**：有线/无线统一为 `channel_ops` 接口，调度层不感知物理差异

## 3. 技术栈

| 维度 | 选型 |
|---|---|
| 网关 | i.MX6ULL（正点原子 MINI）· 嵌入式 Linux · C |
| 节点 | STM32F103（HAL 库）· 有线变体 / 无线变体（固件仅通信层差异） |
| 有线链路 | RS485 半双工 + Modbus RTU（9600 8N1，功能码 0x03） |
| 无线链路 | nRF24L01（SPI 接口 · ShockBurst · 32B 单包 · Modbus 帧透传） |
| 传感器协议 | I2C（SHT30，软件 I2C）· ADC（MQ-2/电压/电流）· 单总线（DHT11 可选） |
| 展示 | LVGL + framebuffer（800×480 @60Hz，fb0 双缓冲 + 脏矩形重绘） |
| 存储 | SQLite（WAL 模式，三表分离） |
| 上云 | MQTT（paho-mqtt-c）→ OneNET 物模型 |
| 驱动 | 设备树 + 自研 nRF24L01 SPI 字符驱动 + LED/按键 miscdevice |
| 工程化 | CMake 交叉编译（arm-linux-gnueabihf）· systemd · 看门狗 |

> 协议覆盖：UART / RS485 / SPI / I2C / 单总线 / ADC / MQTT —— 常见通信协议全占。

## 4. 模块设计要点（九大块速览）

### 4.1 采集节点（STM32F103）
- 一套传感器电路、两种通信变体：有线 = USART1+MAX485（PA8/9/10），无线 = SPI1+nRF24L01（PA3~7/PB0），编译宏区分，PCB 可共用
- ADC1 多通道 + DMA 循环采样；SHT30 用**软件 I2C**（F103 硬件 I2C 有 errata）、带 CRC8、读取间隔 100ms
- Modbus 从站：寄存器区 40001~40008 + 状态字 bit 定义（bit0 传感器故障 / bit1~5 越限），越限主判在网关，节点判定为双保险
- 数据不本地存储（周期采样业务可容忍丢数），只留内存寄存器区

### 4.2 通道抽象层（网关采集域地基）
- `channel_ops` 函数指针表：open / send / recv / close —— 运行期多态
- 职责边界：只搬字节、不解析 Modbus 帧、不重传、不判离线
- **通道 ≠ 节点**：节点注册表多对多绑定，加节点 = 配置加一行
- 价值：mock 通道可单测调度、加蓝牙/4G 链路只加一个实现

### 4.3 Modbus 轮询调度
- 参数全推导：轮询周期 2s（单节点一问一答 ≈25~30ms，占周期 <5%）· 应答超时 200ms · 连续 3 次判离线 · 离线降频每 5 轮询 1 次 · 1 次成功即恢复
- 状态机：IDLE → SEND → WAIT → 校验（CRC16 + 异常码 0x83）→ 下一节点，round-robin
- CLOCK_MONOTONIC 单调时钟防 NTP 漂移；节点离线期间数据空缺、UI/云端标注"离线时段"

### 4.4 数据处理与告警
- 流水线：采集快照 → 环形缓冲(30点) → 差异化滤波 → 量程换算 → 三态告警状态机
- 滤波按噪声特性选型：缓变指标（温/湿/电压）滑动平均 5 点；尖峰指标（烟雾/电流）中值 5 点
- 告警状态机 + **迟滞**防抖：55℃ 进入告警、52℃ 退出（面试高频细节）
- 阈值全配置化（`app.conf`）：温度 45/55℃ · 湿度 80/90% · 烟雾 ADC 1800/2800 · 电压 ±5%/±10% · 电流 25/32A

### 4.5 SQLite 存储
- 三表分离：`node_data`（历史，**原始值+滤波值双保留**可溯源）· `cache_queue`（断网补传，ts 升序 + (node_id,ts) 幂等去重）· `alarm_log`（告警事件 + 阈值快照）
- WAL 模式（处理线程写 / UI、MQTT 线程读并发不互斥）；批量事务提交；30 天保留 + VACUUM
- 容量预算：≈4.3MB/天/2 节点，断网一周 ~25MB，SD 卡无压力

### 4.6 LVGL 展示（800×480）
- 四页面 + 常驻状态栏：实时仪表盘（6 指标卡片+节点切换）/ 历史曲线（环形缓冲 60s + SQLite 两级）/ 告警记录 / 系统状态
- UI 用**共享快照**（覆盖写、多读者）而非队列（消费即消失）；锁内仅 memcpy，绝不持锁重绘
- 三档刷新：LCD 物理 60Hz / LVGL 脏矩形按需重绘 / 数据 500ms~1s（lv_timer 驱动）
- UI 线程优先级**低于**采集线程——"UI 可以卡，数据不能丢"

### 4.7 MQTT 上报（OneNET）
- 两类数据两种节奏：属性聚合 5s 上报一次（全节点合并）；告警事件状态转移即时推送
- 重连：指数退避 1s→30s 封顶 + ±20% 随机抖动（防同步风暴）
- 补传：先存量后实时、按 ts 升序、每轮 20 条限流（防刷爆 broker）
- 三件套：KeepAlive=60s · CleanSession=0 会话续传 · LWT 遗嘱

### 4.8 Linux 驱动（三个工作点）
1. **设备树 bring-up**：uart1/uart3+方向脚/ecspi1+nrf24l01/lcdif/gpio-keys/led 节点梳理与 pinmux 配置，验证链（/proc/device-tree、uevent、fbset、/proc/interrupts）
2. **nRF24L01 内核 SPI 字符驱动**（最高含金量）：spi_driver 匹配 compatible、spi_sync 传输、GPIO 中断 + workqueue 底半部、mutex/spinlock 并发保护、file_operations（read/ioctl）
3. **LED/按键驱动**：miscdevice 状态灯（write 控制）+ input 子系统按键切页，形成"驱动→应用"闭环

### 4.9 失联数据策略（两种失联分开）
- 节点↔网关失联：节点不存数据（业务可容忍），网关标记离线 + 记录断联时段，恢复自动接回
- 网关↔云端断网：数据落 SQLite 带时间戳，恢复后按序补传 + 时间戳去重（幂等）

## 5. 协议契约（已写死，防返工）

**Modbus 寄存器映射（主从双方契约）：**

| 地址 | 含义 | 类型 |
|---|---|---|
| 40001 | 温度 | int16 ×10 |
| 40002 | 湿度 | uint16 ×10 |
| 40003 | 烟雾 | uint16（ADC） |
| 40004~05 | 电压 | uint32 ×100 |
| 40006~07 | 电流 | uint32 ×1000 |
| 40008 | 状态字 | bit0 故障 / bit1~5 越限 |

**OneNET MQTT：** Broker `mqtt.heclouds.com:1883` · ClientID=设备名 / Username=产品ID / Password=设备密钥 · Topic `$sys/{产品ID}/{设备名}/thing/property/post` · 物模型 JSON 属性上报

## 8. 面试高频问答（12 道，含简答）

1. **为什么用 Modbus RTU？** → 工业标准、CRC 校验、寄存器语义清晰、多厂商兼容
2. **RS485 单主多从，冲突怎么办？** → 主站轮询一问一答，从站只在被询时应答
3. **为什么加无线链路？** → 覆盖布线困难场景；通道抽象层统一调度，体现架构设计能力
4. **QoS 0/1/2 区别，为什么用 QoS1？** → 最多一次/至少一次/恰好一次；QoS1 平衡可靠性与开销，配合时间戳去重实现幂等
5. **断网了数据怎么办？** → SQLite 本地缓存 + 恢复后按时间戳补传 + (node_id, ts) 去重
6. **节点失联怎么办？** → 轮询超时 3 次判离线、降频探测、恢复即接回；环境监测可容忍周期空缺
7. **滤波放哪？** → 主滤波在网关（薄节点厚网关），节点只做限幅硬保护 + 状态字双保险
8. **告警为什么加迟滞？** → 防止临界值抖动导致告警频繁响停（55℃ 进 52℃ 出）
9. **LVGL 刷新机制？** → lv_timer_handler 周期调用 + 脏矩形按需重绘，60Hz 是屏幕上限不是重绘频率
10. **UI 线程怎么拿数据？** → 共享快照（覆盖写）而非队列，锁内仅 memcpy，避免持锁重绘
11. **设备树和驱动怎么配合？** → compatible 匹配 spi_driver；自定义属性 of_property_read 解析；中断映射 request_irq
12. **多线程如何共享数据？** → 队列 + 互斥锁生产者-消费者，避免竞态

## 9. 风险与对策（摘要）

| 风险 | 对策 |
|---|---|
| LVGL 移植复杂 | 先 framebuffer + 键盘调试，再适配触摸 |
| RS485 方向切换时序 | GPIO 控制 DE/RE，预留延时 |
| 无线链路穿金属衰减 | 无线只做扩展链路，主线走 RS485 |
| 驱动开发超时 | 两段式：先串口透传打通链路，再升级内核驱动 |
| OneNET 鉴权信息 | 配置文件集中管理，不入库不入代码 |
