## 1. 优先级定义（冲刺的核心纪律）

| 级别 | 含义 | 处理原则 |
|---|---|---|
| **P0** | 没有它项目不成立 | 必做，通宵也要做 |
| **P1** | 直接关联简历加分 | 主线跑通后有余力再做 |
| **P2** | 加分但耗时 | **砍掉或降级**，不做也不影响演示 |

### P0（必做，共 6 块）
1. STM32 采集：SHT30（或 DHT11）温湿度 + 电压 + 电流（ADC 多通道）
2. STM32 Modbus 从站：寄存器区 + 功能码 03 + CRC16
3. RS485 链路：MAX485 双向 + 网关串口
4. 网关应用：串口打开 → Modbus 主站轮询 → 基础滤波/阈值
5. LVGL：单页实时仪表盘（6 指标数值 + 状态色块）
6. MQTT：属性上报 OneNET，云端能看到数据

### P1（尽力而为）
- 告警事件即时上云（非聚合）
- 历史曲线页（简单折线）
- SQLite 落库 node_data（哪怕不查，先记着）
- systemd 开机自启
- 第二采集节点

### P2（砍掉 / 降级，明确放弃清单）
| 原计划内容 | 降级方案 |
|---|---|
| nRF24L01 **内核 SPI 驱动** | 无线若必须做 → 用**串口透传模块**当第二个串口接（2 小时）；来不及 → **纯 RS485**，简历写"设计双链路通道抽象方案" |
| SQLite 断网补传 cache_queue | 砍，只留 node_data；断网场景口头讲方案即可 |
| 设备树深度梳理 / 自编译内核 | 砍，用正点原子**出厂内核**，不碰内核编译 |
| LED/按键 miscdevice 驱动 | 砍 |
| LVGL 多页面（曲线/告警/系统） | 单页仪表盘优先，曲线页 P1 |
| 多节点分布式 | 先单节点跑通，有余力加第 2 个 |

## 2. 每日计划

### Day 1｜环境 + 地基（P0）
| 任务 | 说明 |
|---|---|
| 注册 OneNET | 创建产品（物模型：温度/湿度/烟雾/电压/电流/状态）、创建设备，**记下 ClientID/Username/Password 三要素** |
| 交叉编译链 | 装 arm-linux-gnueabihf-gcc（apt 或正点原子工具包），`arm-linux-gnueabihf-gcc -v` 通过 |
| 板子 bring-up | 烧出厂系统，SSH 登录，确认 `/dev/ttymxc*`、LCD 正常 |
| STM32 空工程 | 基于正点原子/野火 HAL 例程新建，配好 USART1 + RS485 方向脚，能编译能下载 |
| 采购检查 | 缺货模块立刻下单（SHT30/MAX485/ACS712） |

**里程碑**：板子系统可登录、STM32 工程可烧录、OneNET 账号就绪。
**当天收尾原则**：所有东西今天必须"能跑/能登录/能烧录"，不留半成品。

---

### Day 2｜STM32 采集 + 从站（P0）
| 任务 | 说明 |
|---|---|
| SHT30 驱动 | 软件 I2C（PB6/PB7，避开 F103 硬件 I2C errata），100ms 间隔读温湿度，CRC8 校验 |
| ADC 多通道 | ADC1 + DMA：电压（分压）/ 电流（ACS712 分压）/ MQ-2，软件取平均 |
| Modbus 从站 | 寄存器区实现（40001 温度/40002 湿度/40003 烟雾/40004~07 电压电流/40008 状态字），功能码 03，CRC16 |
| 串口调试 | 用电脑串口助手 / ModbusPoll 工具验证能读到寄存器 |

**里程碑**：电脑上 Modbus 调试工具能读到节点数据。
**省时提示**：SHT30/ADC 例程从正点原子或野火库改，别从寄存器裸写。

---

### Day 3｜RS485 联调 + 网关主站（P0）
| 任务 | 说明 |
|---|---|
| 接线 | STM32 MAX485(A/B) ↔ 网关串口 MAX485(A/B)，共地，两端 120Ω 终端电阻 |
| 链路验证 | 网关侧 Python（pyserial）或 minicom 先读到帧，确认方向控制/波特率 9600 8N1 |
| 网关工程 | CMake 工程 + 串口打开（ttymxc3）+ Modbus 主站：帧组装/CRC/轮询/200ms 超时 |
| 简化说明 | 1 周内**不实现通道抽象层**，串口直调；参数照 `modbus-polling.md`（2s 周期/200ms 超时/3 次离线） |

**里程碑**：网关程序能轮询读到节点温湿度/电压电流。
**关键**：今天目标是"网关 CPU 里看到数据"，UI/上云都还不碰。

---

### Day 4｜处理 + LVGL 显示（P0）
| 任务 | 说明 |
|---|---|
| 数据处理 | 滑动平均（温/湿/压）+ 中值（烟/流），窗口 5 点；阈值告警状态机（参数用 `data-processing.md` 参考值，先能出状态） |
| LVGL 移植 | **基于正点原子 LVGL 例程改**，别从零移植；fb0 直驱，lv_tick 用定时器 |
| 仪表盘页 | 单页：6 个指标卡片（大字数值 + 绿/黄/红状态色块）+ 顶部状态栏（时间/节点在线数） |
| SQLite（P1） | 交叉编译 sqlite3，落 node_data（raw + 滤波值 + ts），1s 批量提交 |

**里程碑**：屏幕上看到实时数据，且数据同时落库。
**省时提示**：LVGL 例程改布局远比从零移植快，Layout 用简单绝对坐标，别学官方复杂布局。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| LVGL 交叉编译卡住 | 用正点原子现成 LVGL 例程，只改界面代码 |
| SHT30 没到货 | 先用 DHT11（代码已留双方案），到了再换 |
| paho 交叉编译报错 | 用 `-static` 静态编译；或找 OneNET 官方 SDK（自带编译脚本） |
| 网关串口不通 | 先 minicom 手工发 0x03 帧验证，再上程序；检查 RE/DE 方向脚 |
| 时间不够 | 每天按 P0 列表检查，P1/P2 果断放弃 |
