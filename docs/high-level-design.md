## 2. 系统架构设计

### 2.1 三层架构

```
┌─────────────────────────────────────────────────────────────────┐
│  应用层 · OneNET Studio（物模型属性 · 数据曲线 · 告警推送）          │
│                ▲  MQTT over TCP:1883 · QoS1 · 断线重连 · 离线补传   │
├─────────────────────────────────────────────────────────────────┤
│  汇聚层 · i.MX6ULL 网关（正点原子 MINI · Cortex-A7 · Linux）        │
│                                                                   │
│   ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐        │
│   │ 采集线程  │→│ 处理线程  │→│ MQTT线程  │  │  UI线程  │        │
│   │Modbus主站 │  │滤波/告警 │  │上报/补传 │  │LVGL展示  │        │
│   └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘        │
│        │   通道抽象层(channel_ops)   │             │              │
│   ┌────┴────┐                  ┌────┴────┐  ┌─────┴──────┐      │
│   │rs485_ch │                  │SQLite   │  │共享快照     │      │
│   │rf24_ch  │                  │WAL模式  │  │(锁内memcpy) │      │
│   └────┬────┘                  └─────────┘  └────────────┘      │
│        │  RS485总线 / 2.4GHz无线                                   │
├────────┴────────────────────────────────────────────────────────┤
│  感知层 · STM32F103 节点 × N（Modbus 从站 · 薄节点架构）            │
│   SHT30(I2C)温湿度 · MQ-2(ADC)烟雾 · 电压电流(ADC) · 蜂鸣器告警    │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 部署视图

| 层 | 部署位置 | 运行环境 |
|---|---|---|
| 感知层 | 各充电桩位（现场） | STM32F103 裸机/HAL，5V 供电 |
| 汇聚层 | 充电站控制柜内 | i.MX6ULL Linux，eMMC/SD 存储 |
| 应用层 | OneNET 云端 | MQTT Broker + 物模型平台 |

物理连接：有线节点经 RS485 总线手拉手接入网关串口；无线节点经 2.4GHz 射频接入网关 SPI（nRF24L01）。

### 2.3 核心架构决策

| 决策 | 理由 |
|---|---|
| 薄节点厚网关 | 算力匹配、参数统一管理、支持热更新、原始数据可溯源 |
| 单进程多线程 | 队列+互斥锁解耦四域，生产者-消费者模型 |
| 通道抽象层 | 屏蔽有线/无线物理差异，调度层零感知，支持扩展与单测 |
| 滤波主判在网关 | 节点保持薄而可靠；边缘计算的具体落点 |
| 断网缓存 + 补传 | 保证数据不丢失；时间戳幂等去重 |

## 3. 模块设计

### 3.1 采集节点（STM32F103）固件

```
┌─────────────────────────────────────┐
│           Modbus 从站层              │
│   (USART中断收帧 / CRC16 / 响应组装)  │
├──────────────┬──────────────────────┤
│  寄存器区     │   通信变体层           │
│ 40001~40008  │ 有线: MAX485方向控制   │
│ (共享内存)    │ 无线: nRF24L01 SPI    │
├──────────────┴──────────────────────┤
│           传感器驱动层                │
│ SHT30(I2C) · MQ-2(ADC) · 电压(ADC)  │
│ 电流(ACS712/ADC) · DHT11(单总线,可选)│
├─────────────────────────────────────┤
│           HAL / 硬件层               │
│  ADC1+DMA · USART1 · SPI1 · GPIO    │
└─────────────────────────────────────┘
```

| 模块 | 职责 | 设计要点 |
|---|---|---|
| 传感器驱动层 | 采集温湿度/烟雾/电压/电流 | SHT30 软件 I2C（规避 F103 硬件 I2C errata）；ADC1 多通道+DMA 循环；编译宏切换 SHT30/DHT11 |
| 寄存器区 | 存放最新采集值，供 Modbus 读取 | 共享内存 + 关中断保护（采集更新 vs Modbus 读取并发） |
| Modbus 从站 | 响应 0x03 读寄存器请求 | CRC16 校验；从收到请求到响应 ≤50ms |
| 通信变体层 | 有线/无线物理收发 | 编译宏 `NODE_LINK_RS485`/`NODE_LINK_RF24` 区分；有线 = PA8 方向控制，无线 = SPI 32B 单包 |

#### 3.2.1 采集域

| 子模块 | 职责 | 设计文档 |
|---|---|---|
| 通道抽象层 | 统一 RS485/无线收发接口（channel_ops 函数指针表） | channel-abstraction.md |
| 节点注册表 | 管理节点（地址、通道绑定、在线状态、失败计数、寄存器快照） | channel-abstraction.md §4 |
| Modbus 主站 | round-robin 轮询、帧组装、CRC 校验、超时重试、离线判定 | modbus-polling.md |

**通道抽象层接口：**

```c
struct channel_ops {
    int  (*open) (struct channel *ch);
    int  (*send) (struct channel *ch, const uint8_t *buf, uint16_t len, int timeout_ms);
    int  (*recv) (struct channel *ch, uint8_t *buf, uint16_t maxlen, int timeout_ms);
    void (*close)(struct channel *ch);
};
struct channel {
    const struct channel_ops *ops;
    void *priv;
    char  name[16];
    int   last_errno;
};
```

职责边界：只搬字节、不解析帧、不重传、不判离线。半双工方向控制对上层透明。

**轮询调度参数：**

| 参数 | 值 | 依据 |
|---|---|---|
| 轮询周期 | 2s | 单节点一问一答 ≈25~30ms，3 节点整轮 <100ms，占周期 <5% |
| 应答超时 | 200ms | 正常 30ms 的 6~10 倍 |
| 离线阈值 | 连续 3 次失败 | 容忍瞬时干扰，3 次判真离线 |
| 离线降频 | 每 5 轮询探测 1 次 | 死节点不拖累在线节点 |
| 恢复 | 1 次成功即恢复 | 环境监测容忍短暂抖动 |

调度状态机：IDLE → SEND（组装 0x03 帧）→ WAIT（200ms）→ 成功（CRC+异常码校验 → 更新快照）或超时（fail++ → 3 次离线 → 记断联事件）→ 下一节点。

#### 3.2.2 处理域

| 子模块 | 职责 | 设计文档 |
|---|---|---|

**滤波选型：**

| 指标 | 选型 | 窗口 | 理由 |
|---|---|---|---|
| 温度/湿度/电压 | 滑动平均 | 5 点(10s) | 缓变量，平滑漂移 |
| 烟雾/电流 | 中值滤波 | 5 点(10s) | 有尖峰，中值不被拉偏 |

**告警阈值（配置化，初始参考值）：**

| 指标 | 预警 | 告警 | 迟滞退出 |
|---|---|---|---|
| 温度 | ≥45℃ | ≥55℃ | 52℃ |
| 湿度 | ≥80% | ≥90% | 85% |
| 烟雾 | ADC≥1800 | ADC≥2800 | 2400 |
| 电压 | ±5% | ±10% | ±7% |
| 电流 | ≥25A | ≥32A | 28A |

告警动作：WARN 仅本地标注不打扰；ALARM 触发蜂鸣 + 即时上云。

## 4. 接口设计

### 4.1 外部接口

#### 4.1.1 节点↔网关（Modbus RTU）

| 项 | 值 |
|---|---|
| 物理层 | RS485 半双工差分 / nRF24L01 2.4GHz |
| 链路协议 | Modbus RTU（有线）/ ShockBurst + Modbus 帧透传（无线） |
| 串口参数 | 9600, 8N1 |
| 功能码 | 0x03（读保持寄存器） |
| 帧校验 | CRC16（多项式 0xA001） |
| 寄存器范围 | 40001~40008 |

**请求帧（主站→从站）：** `从站地址(1B) + 0x03 + 起始寄存器(2B) + 数量(2B) + CRC16(2B)` = 8 字节

**正常响应帧（从站→主站）：** `从站地址(1B) + 0x03 + 字节计数(1B) + 数据(N×2B) + CRC16(2B)`，读 8 寄存器 = 19 字节

**寄存器映射：**

| 寄存器 | 含义 | 类型 | 缩放 |
|---|---|---|---|
| 40001 | 温度 | int16 | ×10（0.1℃） |
| 40002 | 湿度 | uint16 | ×10（0.1%RH） |
| 40003 | 烟雾 | uint16 | ADC 原始值 |
| 40004~40005 | 电压 | uint32 | ×100（0.01V），大端 |
| 40006~40007 | 电流 | uint32 | ×1000（0.001A），大端 |
| 40008 | 状态字 | uint16 | bit0 故障 / bit1~5 越限 |

#### 4.1.2 网关↔云端（MQTT）

| 项 | 值 |
|---|---|
| Broker | mqtt.heclouds.com:1883 |
| 鉴权 | ClientID=设备名 / Username=产品ID / Password=设备密钥 |
| 属性 Topic | `$sys/{产品ID}/{设备名}/thing/property/post` |
| QoS | 1（至少一次 + 时间戳去重） |
| KeepAlive | 60s |
| CleanSession | 0（会话续传） |
| LWT | 遗嘱消息（异常离线通知） |

|---|---|---|
| 采集→处理 | 队列 + 互斥锁 | 寄存器快照 |

## 6. 运行设计

### 6.1 线程模型

网关单进程四线程，优先级：采集 > 处理 > MQTT > UI。

| 线程 | 职责 | 同步方式 |
|---|---|---|
| 采集线程 | Modbus 主站轮询，更新寄存器快照 | 队列推送到处理线程 |
| 处理线程 | 滤波、量程换算、告警判定 | 队列接收；共享快照给 UI；队列推送 MQTT |
| MQTT 线程 | 属性聚合上报、告警即时上报、重连、补传 | 队列接收；SQLite 读写 |
| UI 线程 | LVGL 页面渲染、数据刷新 | 共享快照读取（锁内 memcpy） |

### 6.2 关键状态机

#### 6.2.1 轮询调度状态机

```
        ┌────────┐
        │  IDLE  │←─────────────────────┐
        └───┬────┘                      │
            │ 取下一节点                 │
        ┌───┴────┐                      │
        │  SEND  │ 组装0x03帧 → send()  │
        └───┬────┘                      │
            │                           │
        ┌───┴────┐   200ms超时          │
        │  WAIT  │──────────→ fail++ ──┤
        └───┬────┘                      │
            │ 收到响应                    │
            ↓                           │
      CRC+异常码校验                      │
       │        │                       │
     成功      失败 ────────────────────→│
       │                                │
   更新快照                               │
   fail=0                                │
   ONLINE                                │
       │                                │
       └────────────────────────────────┘
              等待轮询间隔(2s)
```

#### 6.2.2 告警状态机（以温度为例）

```
            ┌────────┐
            │ NORMAL │
            └───┬────┘
                │ 温度 ≥ 45℃
            ┌───┴────┐
            │  WARN  │ (本地标注，不上云)
            └───┬────┘
                │ 温度 ≥ 55℃          52℃ 退出
            ┌───┴────┐ ──────────→ NORMAL
            │ ALARM  │ (蜂鸣 + 即时上云)
            └────────┘
```

迟滞：进入告警 55℃、退出 52℃，防止临界值抖动导致告警频繁响停。

#### 6.2.3 MQTT 重连状态机

```
DISCONNECTED → CONNECTING(5s超时) → CONNECTED
     ↑                │                    │
     │           失败/超时                 │ 网络断开
     │                ↓                    │
     └──── 退避等待(1s~30s+抖动) ←─────────┘
```

### 6.3 关键时序

#### 6.3.1 正常采集→上报时序

```
节点        网关采集线程    处理线程    MQTT线程    OneNET
 │              │             │          │          │
 │←─轮询请求────│             │          │          │
 │──响应数据───→│             │          │          │
 │              │──快照入队──→│          │          │
 │              │             │─滤波/告警│          │
 │              │             │──数据入队→│          │
 │              │             │          │─聚合5s──→│
 │              │             │          │          │─存储展示
```

#### 6.3.2 断网→补传时序

```
网关          OneNET
 │              │
 │  断网开始     │
 │  数据→SQLite  │  (cache_queue 积攒)
 │  数据→SQLite  │
 │              │
 │  网络恢复     │
 │  重连成功     │
 │──补传存量────→│  (ts升序, 每轮20条)
 │──补传存量────→│
 │  存量清空     │
 │──切回实时────→│  (新数据直接上报)
```

## 7. 出错处理设计

### 7.1 节点失联

| 场景 | 处理 |
|---|---|
| 单次轮询超时 | fail_count++，继续下一节点 |
| 连续 3 次超时 | 标记 OFFLINE，记录断联事件，降频至每 5 轮询探测 1 次 |
| 离线节点恢复 | 1 次成功即标记 ONLINE，恢复正常轮询频率 |
| 离线期间数据 | 空缺，UI/云端标注"离线时段"，不补传（周期采样业务可容忍丢数） |

### 7.2 网关断网

| 场景 | 处理 |
|---|---|
| MQTT 连接断开 | 采集/处理/UI 不停止，仅上报暂停 |
| 断网期间数据 | 写入 node_data + 入 cache_queue（带时间戳） |
| 网络恢复 | 指数退避重连 → 成功后先补传存量（ts 升序、分批限流 20 条/轮）→ 清空后切回实时 |
| 补传期间新数据 | 直接实时上报，不入队 |
| 补传重复 | (node_id, ts) 幂等去重 |
| 网关重启 | 从 cache_queue 恢复未补传数据 |

### 7.3 数据异常

| 场景 | 处理 |
|---|---|
| CRC 校验失败 | 丢弃该帧，fail_count++ |
| 异常码 0x83 | 计入失败，记日志 |
| 传感器故障（状态字 bit0） | 标记该指标异常，UI 标红，不参与告警判定 |
| ADC 值超物理量程 | 节点侧限幅丢弃（硬保护） |
| SHT30 CRC8 校验失败 | 连续 N 次置状态字 bit0 |

### 7.4 系统级容错

| 场景 | 处理 |
|---|---|
| 网关进程崩溃 | systemd 自动重启 |
| SQLite 写入失败 | 记日志，降级为仅内存处理（不落库） |
| LVGL 渲染异常 | 不影响采集/处理/上报（UI 线程独立） |
| 时钟漂移 | 采集调度用 CLOCK_MONOTONIC（不受 NTP 影响）；SQLite 时间戳用本地时间 |

## 9. 设计决策汇总

| # | 决策 | 理由 | 对应需求 |
|---|---|---|---|
| D1 | 薄节点厚网关 | 算力匹配、参数统一、热更新、可溯源 | NFR-M01, NFR-M04 |
| D2 | 通道抽象层（函数指针表） | 屏蔽物理差异、可扩展、可单测 | FR-G01, NFR-M03 |
| D3 | Modbus RTU 主线 | 工业标准、CRC 校验、多节点 | FR-N07, FR-G03 |
| D4 | nRF24L01 无线扩展 | 覆盖布线困难场景；不替主线 | FR-N12 |
| D5 | 软件 I2C（SHT30） | 规避 F103 硬件 I2C errata | FR-N01 |
| D6 | 差异化滤波 | 按噪声特性选型，效果最优 | FR-P02, FR-P03 |
| D7 | 告警迟滞 | 防临界抖动 | FR-P06 |
| D8 | SQLite WAL + 批量提交 | 读写并发、写吞吐 | FR-S04, NFR-R01 |
| D9 | 共享快照（UI） | 多读者、锁内仅 memcpy | FR-U06 |
| D10 | QoS1 + 时间戳去重 | 至少一次 + 幂等 | FR-M05 |
| D11 | 指数退避重连 + 抖动 | 防同步风暴 | FR-M06 |
| D12 | 节点失联不补传 | 周期采样业务可容忍丢数 | FR-R02 |
