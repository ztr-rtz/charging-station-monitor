> 输入：docs/modbus-polling.md 的采集快照 ｜ 输出：归一化数据 + 告警状态 → UI / SQLite / MQTT
> 本文只定义设计与参数，不含代码实现。

---

## 1. 定位与数据流水线

处理线程消费采集队列（每节点每 2s 一条原始快照），完成「降噪 → 换算 → 判警」，产出**归一化物理量 + 告警状态**，供展示、存储、上报三个下游使用。

```
采集快照(原始寄存器值)
   → 环形缓冲（每节点每指标 30 点）
   → 滤波（滑动平均 / 中值，按指标特性选型）
   → 量程换算（ADC/寄存器原始值 → 物理量）
   → 阈值告警状态机（正常/预警/告警三态 + 迟滞）
   → 归一化数据 + 告警事件
        ├─→ UI 线程（#7）
        ├─→ SQLite（#6）
        └─→ MQTT 上报（#8）
```

---

## 2. 环形缓冲

- 结构：每节点 × 每指标一个环形缓冲，深度 **30 点**（2s 周期 → 覆盖最近 60s）
- 作用：为滤波提供窗口数据，同时支持 UI 画最近 1 分钟曲线（不用额外存历史）
- 深度依据：滤波窗口最大 5 点，30 点窗口够曲线展示且内存开销小（5 指标 × 30 × 4B ≈ 600B/节点，可忽略）

---

## 3. 滤波策略（按噪声特性选型，不是一刀切）

| 指标 | 噪声特性 | 选型 | 窗口 | 理由 |
|---|---|---|---|---|
| 温度 / 湿度 | 缓变、无尖峰 | **滑动平均** | 5 点（10s） | 平滑漂移，响应延迟可接受 |
| 烟雾（MQ-2） | 传感器输出波动大、偶发尖峰 | **中值滤波** | 5 点（10s） | 剔除尖峰优于平均（平均会被尖峰拉偏） |
| 电压 | 电网抖动、偶发毛刺 | 滑动平均 | 5 点（10s） | 兼顾平滑与响应 |
| 电流 | 负载突变、采样尖峰 | **中值滤波** | 5 点（10s） | 尖峰是假象，中值最稳 |

> 面试点：能讲出「滑动平均适合缓变量、中值适合尖峰噪声」的选型逻辑，比"我用了滤波"高一个档次。窗口 5 点 = 10s 时间常数，环境量这个响应速度完全够。

---

## 4. 量程换算公式（原始值 → 物理量）

| 指标 | 原始值 | 换算公式 | 说明 |
|---|---|---|---|
| 温度 | SHT30 寄存器 16bit | T = -45 + 175 × raw / 65535（℃） | SHT30 数据手册标准公式 |
| 湿度 | SHT30 寄存器 16bit | RH = 100 × raw / 65535（%RH） | 同上 |
| 烟雾 | MQ-2 ADC 12bit（0~4095） | V = raw × 3.3 / 4095（V）；浓度曲线待标定（§遗留） | 先报电压/ADC 值，ppm 标定后升级 |
| 电压 | ADC 12bit | V_in = raw × 3.3 / 4095 × 分压比（分压比如 30k/10k → ×4） | 分压比在 node-design 标定 |
| 电流 | ACS712 ADC 12bit | I = (V - V_offset) / 灵敏度（如 66mV/A） | ACS712-20A 灵敏度 100mV/A，型号确定后定 |

> 公式集中在一张换算表，代码里做成查表/映射函数，禁止散落各处——这是「量程换算集中管理」的工程习惯。

## 5. 告警阈值表（初始参考值，可配置，联调时标定）

**阈值全部放配置文件 `app.conf`，不硬编码**；下列为初始参考值，阶段 2 联调按实际环境修正。

| 指标 | 预警（WARN） | 告警（ALARM） | 迟滞（退出阈值） | 依据 |
|---|---|---|---|---|
| 温度 | ≥45℃ | ≥55℃ | 告警退出 52℃ | 充电桩机柜环境温度上限参考；可调 |
| 湿度 | ≥80%RH | ≥90%RH | 告警退出 85% | 高湿易凝露，绝缘风险 |
| 烟雾 | ADC ≥1800（≈1.45V） | ADC ≥2800（≈2.26V） | 退出 2600 | 可燃气体浓度上升即预警，标定后改 ppm |
| 电压 | <209V 或 >231V（±5%） | <198V 或 >242V（±10%） | 回归 201~239V | 国标 220V±10%；±5% 预警合理 |
| 电流 | ≥25A | ≥32A | 退出 30A | 参考单桩额定 32A 配置；按实际断路器规格调 |

**迟滞（Hysteresis）设计说明：**

- 进入阈值 ≠ 退出阈值：告警在 55℃ 触发，但回落到 52℃ 才解除
- 作用：防止临界值抖动导致告警频繁"响-停-响"（蜂鸣器/云端通知最怕这个）
- 这是状态机设计里最实用的细节，面试直接问「为什么告警要加迟滞」就能答

## 6. 告警状态机（三态 + 迟滞）

```
              ┌─────────── 超预警阈值（WARN 上沿） ───────────┐
              ▼                                             │
      ┌───────────┐        ┌───────────┐      ┌───────────┐ │
      │  NORMAL   │ ─────► │   WARN    │ ───► │  ALARM    │ │
      │  正常     │        │  预警     │      │  告警     │ │
      └───────────┘        └───────────┘      └───────────┘ │
              ▲             │         ▲            │        │
              │             │         │            │        │
              │     回落 WARN 下沿    │     回落告警退出阈值  │
              └─────────────┴─────────┴────────────┘────────┘
```

**动作语义：**

| 转移 | 触发 | 动作 |
|---|---|---|
| NORMAL → WARN | 超预警上沿 | UI 黄色标记；不打扰（不蜂鸣、不上云告警） |
| WARN → ALARM | 超告警上沿 | 置 40008 告警位 + 事件入 SQLite + **MQTT 告警上报** + 本地蜂鸣/LED（如启用） |
| ALARM → WARN/NORMAL | 回落退出阈值 | 记录恢复事件，上云恢复上报，解除本地告警 |
| 任意 → 任意 | 节点离线 | 由采集域离线事件驱动（告警态冻结为"未知"，恢复后重新判警） |

> 设计点：**告警在边缘判定，云上只收结果与事件**——这就是"边缘计算"在项目里的具体落点，也是简历核心卖点之一。

## 7. 面试价值点

1. **滤波选型逻辑**：按信号噪声特性差异化选型（滑动平均 vs 中值），不是模板式套用
2. **迟滞防抖**：状态机工程化的经典细节
3. **边缘计算**：本地判警、云端收结果——流量成本与实时性的平衡
4. **配置化**：阈值全配置化不硬编码，联调标定是测试方法论
5. **换算集中管理**：量程公式一张表，工程可维护性

**简历 bullet 参考：**
> 实现网关边缘处理流水线：按噪声特性为各指标差异化选型滤波（滑动平均/中值），三态告警状态机带迟滞防抖，阈值全配置化；告警本地判定、云端仅收事件，体现边缘计算架构。
