---

## 1. 定位与职责

通道抽象层是网关采集线程内部的**物理链路统一接口**：把 RS485 有线、nRF24L01 无线两种物理通道抽象成同一套收发接口，上层（Modbus 轮询调度、数据解析、超时处理）只认这套接口，**不知道底层是电线还是电波**。

```
                    ┌──────────────────────────────┐
                    │  轮询调度层（Modbus 主站逻辑） │  ← 只认 channel 接口
                    └──────────────┬───────────────┘
                        send() / recv() / open() / close()
                    ┌──────────────┴───────────────┐
                    │        通道抽象层             │
                    │   channel = { ops, priv }     │
                    └──┬───────────────────┬───────┘
                 rs485_channel       rf24_channel
                 （串口+MAX485）      （nRF24L01/SPI）
```

**职责边界（面试重点，写死三句话）：**

1. **只做字节的可靠搬运**——不解析 Modbus 帧（帧解析属于轮询调度层）
2. **不做重传**——重传、失败计数是调度层的策略，通道层只管"发出去了/超时了"
3. **不判断节点在线离线**——离线判定由调度层基于超时统计完成

> 好处：新增一种物理链路（如蓝牙、4G 模块）只需新增一个 channel 实现，调度层零改动；测试时可以用 mock 通道替身，不依赖硬件就能单测轮询逻辑。

## 2. 接口定义（函数指针表）

C 语言用「结构体 + 函数指针」实现接口多态，这是本设计的核心：

```c
/* 通道方法表：一种物理链路 = 一组实现 */
struct channel_ops {
    int  (*open) (struct channel *ch);
    int  (*send) (struct channel *ch, const uint8_t *buf, uint16_t len, int timeout_ms);
    int  (*recv) (struct channel *ch, uint8_t *buf, uint16_t maxlen, int timeout_ms);
    void (*close)(struct channel *ch);
};

/* 通道句柄：上层拿到的唯一对象 */
struct channel {
    const struct channel_ops *ops;  /* 方法表（static 常量，不可变） */
    void *priv;                     /* 实现私有数据：串口 fd / GPIO 句柄 / 驱动 fd 等 */
    char  name[16];                 /* 调试用："rs485" / "rf24" */
    int   last_errno;               /* 最近一次错误码，供日志与统计 */
};
```

**接口语义约定：**

| 接口 | 语义 | 返回值约定 |
|---|---|---|
| `open()` | 打开/初始化物理链路（串口配置、GPIO 方向脚、SPI 驱动握手） | 0 成功；负值失败（-ENODEV 等） |
| `send()` | 发送一帧，同步阻塞直到写完 | 0 成功；-ETIMEDOUT 发送超时；-EIO 链路异常 |
| `recv()` | 等待一帧应答，阻塞至超时 | 0 成功且 `len>0`；-ETIMEDOUT 无应答；-EIO 链路异常 |
| `close()` | 关闭释放 | 无 |

**关键约定：**

1. **半双工方向控制（RS485 的 RE/DE）由实现内部处理，对上层透明**——上层调 `send()` 就知道发完了、调 `recv()` 就知道在等应答，不关心 GPIO 时序
2. `timeout_ms` 由调用方（调度层）传入，通道层只负责按此超时返回，**超时判定权在上层**
3. `send()`/`recv()` 均为**同步阻塞**语义，调用方是唯一的采集线程，无并发问题（如未来多线程收发，再在实现内部加锁）
4. 无线通道的 32B 单包限制由实现内部保证：`send()` 收到超过 32B 的帧返回 -EMSGSIZE，上层不感知

## 3. 两种通道实现要点

| 项 | rs485_channel | rf24_channel |
|---|---|---|
| 底层资源 | 串口 fd（termios 9600 8N1）+ 1 个 GPIO（方向控制） | nRF24L01 字符设备 fd（自写内核驱动，§6.3②；备选 spidev） |
| `open()` | 打开串口、配置 termios、初始化方向 GPIO 为接收态 | 打开驱动、配置信道/速率、使能接收管道 |
| `send()` | DE 拉高 → write → 等发送完成 → DE 拉低 | 写入 TX 缓冲 + CE 脉冲，等待自动应答 ACK |
| `recv()` | 读串口攒字节，按帧间静默（3.5 字符时间）判定帧结束 | 等待一包（strip 自动应答位），≤32B |
| 数据约束 | 无 | 单包 ≤32B（Modbus 请求 8B / 响应 9B，可容纳） |
| 挂载节点数 | 1 个通道可挂 **N 个从站**（总线并联，靠地址区分） | 1 个通道可挂 **≤6 个从站**（6 个接收管道） |

**关键概念：通道 ≠ 节点，多对多由注册表管理（§4）**

- 通道 = 一条**物理链路**
- 节点 = 一个**逻辑从站**（Modbus 地址）
- 同一个 rs485_channel 可被节点 1、节点 2 共享；rf24_channel 同理（管道 0~5）

## 4. 节点注册表与调度关系

```c
struct node {
    uint8_t  addr;              /* Modbus 从站地址 1~N */
    struct channel *ch;         /* 绑定的通道（可多节点共享同一 ch） */
    enum { NODE_OFFLINE, NODE_ONLINE } state;
    uint16_t fail_count;        /* 连续失败计数 */
    uint64_t last_poll_ms;      /* 上次轮询时间戳 */
    uint16_t regs[8];           /* 最近一次读回的寄存器快照（供处理域消费） */
};
```

- **节点表与通道表分离**：`struct channel channels[]`（每种物理链路一份）+ `struct node nodes[]`（每个从站一份）
- 配置由 `app.conf` 描述：`[channel]` 段定义链路，`[node]` 段定义 `addr + channel 名`，程序启动时绑定
- 新增节点 = 改配置加一行，不动代码——这是"分布式可扩展"在网关侧的落点

**调度骨架（细节在待补 #4 轮询时序中细化）：**

```
for (;;) {
    node = 取下一个节点（轮转）;
    ret = node->ch->send(...);            // 组装 Modbus 请求帧 → 发送
    ret = node->ch->recv(..., timeout=200ms);  // 等应答
    if (成功) { 校验 CRC → 更新 node->regs → fail_count=0 → ONLINE; }
    else      { fail_count++; 连续 3 次 → OFFLINE + 记录断联事件; }
    等待轮询间隔（2s）;
}
```

## 5. 错误语义与上层动作

| 返回 | 含义 | 调度层动作 |
|---|---|---|
| 0 | 成功 | 解析数据、更新快照 |
| -ETIMEDOUT | 节点无应答 | 失败计数 +1（最常见：节点断电/链路断） |
| -EIO | 链路级异常（串口失效/无线模块故障） | 尝试 `close()` + `open()` 重初始化 |
| -EMSGSIZE | 帧超长（仅无线） | 丢弃，记日志（正常不会出现） |
| -EINVAL | 非法参数 | 配置错误，启动时即暴露 |

## 6. 面试价值点

1. **接口抽象 / 依赖倒置**：上层依赖抽象接口而非具体链路——"面向接口编程"在嵌入式 C 里的落地
2. **C 语言多态**：函数指针表实现运行期多态，与 C++ 虚函数对照可讲
3. **可测试性**：mock channel 替身 → 不接硬件先单测轮询调度、超时重试逻辑
4. **可扩展性**：加一种链路只加一个实现（蓝牙/4G/以太网同理）
5. **分层思想**：物理层（串口/SPI）→ 链路层（通道）→ 应用层（Modbus）→ 业务层（数据/告警），每层职责单一

**简历 bullet 参考：**
> 设计网关采集通道抽象层（函数指针接口，屏蔽 RS485 与 nRF24L01 物理差异），节点注册表统一调度双链路混合组网，支持节点热插拔与故障隔离，新增链路零侵入。
