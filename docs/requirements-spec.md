## 1. 引言

### 1.1 目的

本文档定义「分布式充电站环境检测系统」的功能需求、非功能需求、约束条件与接口需求，作为设计、开发、验收的基准。目标读者：项目开发者（本人）、评审者（面试官）、后续维护者。

### 1.2 范围

系统覆盖从感知层（STM32 采集节点）到汇聚层（i.MX6ULL 网关）再到应用层（OneNET 云平台）的三层全链路，包含：多节点环境数据采集、RS485/无线双链路传输、网关边缘处理与本地展示、MQTT 上云与断网缓存补传。

不在范围内：充电桩功率控制与计费、充电协议（GB/T 27930）、云端业务系统（用户管理/订单）、移动端 App 开发。

### 1.3 术语与缩略语

| 术语 | 说明 |
|---|---|
| 节点 / 采集节点 | STM32F103 采集设备，Modbus 从站 |
| 网关 | i.MX6ULL 边缘设备，Modbus 主站 + 数据处理 + 上云 |
| 薄节点厚网关 | 架构原则：节点只采集，处理/告警/存储/上报全在网关 |
| Modbus RTU | 工业现场总线应用协议，主从轮询，功能码 0x03 |
| RS485 | 差分电气标准（非协议），半双工，抗干扰 |
| 通道抽象层 | 网关内部统一 RS485/无线收发的接口层 |
| 物模型 | OneNET 对设备属性的标准化描述 |
| QoS | MQTT 消息质量等级，本项目用 QoS1（至少一次） |
| LWT | Last Will & Testament，MQTT 遗嘱消息 |
| WAL | SQLite Write-Ahead Logging，读写并发模式 |
| 迟滞 | 告警进入与退出使用不同阈值，防临界抖动 |

## 2. 项目背景与目标

### 2.1 背景

充电站（直流快充桩/交流慢充桩）运行环境存在过温、湿度过高、可燃气体泄漏、电压电流异常等安全隐患。现有方案多为单点独立监测，缺乏集中汇聚、边缘告警与远程可视能力。本项目构建分布式采集 + 边缘网关 + 云端监控的三层系统，解决环境参数集中感知与异常及时告警的问题。

本项目同时作为秋招简历项目，需覆盖嵌入式岗位高频考察的技术能力。

### 2.2 目标

| 编号 | 目标 | 验收标准 |
|---|---|---|
| G1 | 多节点分布式环境采集 | ≥1 个节点稳定上报温湿度/烟雾/电压电流 |
| G2 | 工业总线 + 无线双链路 | RS485/Modbus 主线打通；无线链路至少完成方案设计与接口预留 |
| G3 | 网关边缘处理 | 实现滤波、阈值告警、断网缓存 |
| G4 | 本地可视化 | LVGL 800×480 屏幕实时显示采集数据与告警 |
| G5 | 云端远程监控 | OneNET 平台可见实时数据曲线与告警事件 |
| G6 | 断网可靠性 | 断网期间数据不丢失，恢复后自动补传 |
| G7 | 技术覆盖度 | 覆盖 UART/RS485/SPI/I2C/ADC/单总线/MQTT 多种协议 |

### 2.3 用户与角色

| 角色 | 使用方式 | 关注点 |
|---|---|---|
| 现场运维人员 | 查看网关 LVGL 屏幕 | 实时数值、告警状态、节点在线情况 |
| 远程监控人员 | 登录 OneNET 平台 | 历史曲线、告警推送、设备在线状态 |
| 系统开发者 | 代码与文档 | 架构合理性、可维护性、面试可讲性 |

## 3. 功能需求

### 3.1 采集节点（STM32F103）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-N01 | 节点应通过 SHT30（I2C）采集温度与湿度，精度满足 ±0.2℃/±2%RH | P0 |
| FR-N02 | 节点应通过 ADC 采集 MQ-2 烟雾模拟量（ADC 原始值 0~4095） | P0 |
| FR-N03 | 节点应通过 ADC + 分压电路采集电压值 | P0 |
| FR-N04 | 节点应通过 ACS712 霍尔传感器采集电流值 | P0 |
| FR-N05 | 节点应支持 DHT11（单总线）作为温湿度低成本替代方案，编译宏切换 | P2 |
| FR-N06 | 节点应将采集数据存入 Modbus 保持寄存器区（40001~40008），遵循统一寄存器映射 | P0 |
| FR-N07 | 节点应实现 Modbus RTU 从站，响应功能码 0x03（读保持寄存器） | P0 |
| FR-N08 | 节点应计算 CRC16（多项式 0xA001）进行帧校验，校验失败不响应 | P0 |
| FR-N09 | 节点应在 40008 状态字中上报传感器故障位与越限标志位（冗余判定） | P1 |
| FR-N10 | 节点应对 ADC 采样子系统做限幅保护，超出物理量程的值丢弃 | P1 |
| FR-N11 | 节点有线变体应通过 USART + MAX485 实现 RS485 半双工通信，PA8 控制收发方向 | P0 |
| FR-N12 | 节点无线变体应通过 SPI + nRF24L01 实现无线通信，Modbus 帧封装进 32B 单包 | P1 |
| FR-N13 | 节点从收到请求到发出响应应 ≤ 50ms | P1 |
| FR-N14 | MQ-2 上电预热期间（≥60s）数据应标记"预热中"，不参与告警判定 | P1 |

### 3.2 网关采集域（i.MX6ULL）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-G01 | 网关应实现通道抽象层，统一 RS485 与无线通道为 open/send/recv/close 接口 | P0 |
| FR-G02 | 网关应通过节点注册表管理节点，支持节点与通道多对多绑定 | P0 |
| FR-G03 | 网关应实现 Modbus 主站，按 round-robin 轮询各节点寄存器 | P0 |
| FR-G04 | 轮询周期应为 2s，单节点应答超时 200ms | P0 |
| FR-G05 | 节点连续 3 次超时应标记离线，离线节点降频至每 5 轮询探测 1 次 | P1 |
| FR-G06 | 离线节点恢复通信（1 次成功）应立即标记在线 | P1 |
| FR-G07 | 网关应校验响应帧 CRC16 与异常码（0x83），异常时计入失败计数 | P0 |
| FR-G08 | 新增节点应仅通过修改配置文件完成，不改动代码 | P1 |

### 3.3 网关处理域

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-P01 | 网关应维护每指标 30 点环形缓冲区 | P0 |
| FR-P02 | 网关应对缓变指标（温度/湿度/电压）做 5 点滑动平均滤波 | P0 |
| FR-P03 | 网关应对尖峰指标（烟雾/电流）做 5 点中值滤波 | P0 |
| FR-P04 | 网关应对 ADC 原始值做量程换算（SHT30 公式、分压比、ACS712 灵敏度） | P0 |
| FR-P05 | 网关应实现三态告警状态机：正常 → 预警 → 告警 | P0 |
| FR-P06 | 告警状态机应使用迟滞机制（进入阈值高于退出阈值），防止临界抖动 | P0 |
| FR-P07 | 预警（WARN）状态仅本地标注，不上云；告警（ALARM）状态触发蜂鸣 + 上云 | P1 |
| FR-P08 | 所有滤波窗口与告警阈值应通过配置文件管理，不硬编码 | P0 |

### 3.4 网关存储域

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-S01 | 网关应使用 SQLite 存储历史数据、断网缓存队列、告警日志 | P0 |
| FR-S02 | 历史数据表应同时保留原始值与滤波值，支持数据溯源 | P1 |
| FR-S03 | 断网缓存队列应按时间戳升序补传，并以 (node_id, ts) 幂等去重 | P0 |
| FR-S04 | SQLite 应启用 WAL 模式支持读写并发 | P0 |
| FR-S05 | 数据写入应使用批量事务提交 | P1 |
| FR-S06 | 系统应按 30 天保留期自动清理过期数据 | P2 |

### 3.5 网关展示域（LVGL）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-U01 | 网关应通过 LVGL 在 800×480 屏幕上实现监控界面 | P0 |
| FR-U02 | 应提供实时仪表盘页面，显示各节点当前指标数值与状态色块 | P0 |
| FR-U03 | 应提供历史曲线页面，显示近期指标趋势 | P1 |
| FR-U04 | 应提供告警记录页面，按时间倒序列出告警事件 | P1 |
| FR-U05 | 应提供系统状态页面，显示 IP/MQTT 连接/磁盘/节点在线状态 | P1 |
| FR-U06 | UI 线程应通过共享快照获取数据，锁内仅做内存拷贝，不持锁重绘 | P0 |
| FR-U07 | 界面刷新采用脏矩形按需重绘，数据刷新频率 500ms~1s | P0 |

### 3.6 网关上报域（MQTT）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-M01 | 网关应通过 MQTT 协议接入 OneNET 云平台 | P0 |
| FR-M02 | 应使用 OneNET 三要素鉴权（ClientID=设备名/Username=产品ID/Password=设备密钥） | P0 |
| FR-M03 | 属性数据应聚合上报，周期 5s，全节点多属性合并为一条报文 | P0 |
| FR-M04 | 告警事件应在状态机转移时即时上报，不等待聚合周期 | P0 |
| FR-M05 | 应使用 QoS1 保证至少一次投递，配合时间戳去重实现幂等 | P0 |
| FR-M06 | 应实现断线重连，采用指数退避（1s→30s 封顶）+ 随机抖动 | P0 |
| FR-M07 | 断网期间数据应写入缓存队列，重连后先补传存量（按 ts 升序、分批限流），再切回实时 | P0 |
| FR-M08 | 应配置 KeepAlive=60s、CleanSession=0、LWT 遗嘱消息 | P1 |

### 3.7 失联与可靠性

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-R01 | 节点失联时网关应标记离线并记录断联时段，恢复后自动接回 | P0 |
| FR-R02 | 节点失联期间数据空缺，UI 与云端标注"离线时段" | P1 |
| FR-R03 | 网关断网期间采集/处理/UI 不应停止，仅上报暂停 | P0 |
| FR-R04 | 网关重启后应恢复 SQLite 中未补传的缓存数据 | P1 |

## 4. 非功能需求

### 4.1 性能

| 编号 | 需求 |
|---|---|
| NFR-P01 | 采集轮询周期 ≤ 2s，单节点一问一答 ≤ 30ms |
| NFR-P02 | 节点响应延迟 ≤ 50ms |
| NFR-P03 | LVGL 界面数据刷新 ≤ 1s |
| NFR-P04 | MQTT 属性上报延迟 ≤ 5s（正常网络） |
| NFR-P05 | SQLite 单日数据量 ≤ 5MB（2 节点），断网一周 ≤ 30MB |

### 4.2 可靠性

| 编号 | 需求 |
|---|---|
| NFR-R01 | 系统应支持 7×24h 连续运行，无内存泄漏 |
| NFR-R02 | 断网不丢数据，恢复后完整补传 |
| NFR-R03 | 单节点故障不影响其他节点采集与系统运行 |
| NFR-R04 | 网关进程异常退出后应自动重启（systemd 守护） |

### 4.3 可维护性与可扩展性

| 编号 | 需求 |
|---|---|
| NFR-M01 | 滤波参数、告警阈值、节点配置、MQTT 鉴权信息应通过配置文件管理 |
| NFR-M02 | 新增采集节点仅需修改配置文件 |
| NFR-M03 | 新增物理链路类型仅需实现通道抽象层接口，不改动调度层 |
| NFR-M04 | 传感器可替换（SHT30↔DHT11），不影响 Modbus 契约与上层逻辑 |

### 4.4 安全性

| 编号 | 需求 |
|---|---|
| NFR-S01 | OneNET 鉴权密钥不硬编码于源码，通过配置文件加载 |
| NFR-S02 | 配置文件权限限制为仅属主可读写（chmod 600） |

### 4.5 约束条件

| 编号 | 约束 |
|---|---|
| CON-01 | 网关硬件：正点原子 i.MX6ULL MINI（Cortex-A7 @528MHz，512MB DDR，Linux） |
| CON-02 | 节点硬件：STM32F103（HAL 库） |
| CON-03 | 屏幕：800×480 @60Hz |
| CON-04 | 云平台：OneNET Studio |
| CON-05 | 开发语言：C（网关）/ C（STM32 HAL） |
| CON-06 | 工具链：arm-linux-gnueabihf 交叉编译 |
| CON-07 | 构建系统：CMake（网关） |
| CON-08 | 开发周期：1 周冲刺版（P0 优先，P1 按需，P2 降级/砍除） |

### 4.6 优先级定义

| 级别 | 含义 | 冲刺版处理 |
|---|---|---|
| P0 | 必须，核心闭环不可缺 | 必须完成 |
| P1 | 应该，提升完整度与可靠性 | 有余力完成 |
| P2 | 可以，增强特性 | 降级或砍除 |

## 5. 接口需求

### 5.1 外部接口

| 接口 | 类型 | 说明 |
|---|---|---|
| 节点↔网关（有线） | RS485 + Modbus RTU | 9600 8N1，功能码 0x03，寄存器 40001~40008 |
| 节点↔网关（无线） | nRF24L01 2.4GHz + Modbus 帧透传 | SPI 接口，32B 单包，增强型 ShockBurst |
| 网关↔云端 | MQTT over TCP:1883 | OneNET 物模型 JSON，QoS1 |
| 网关↔显示 | Linux framebuffer | 800×480，fb0 双缓冲 |
| 网关↔运维 | 调试串口 / SSH | 终端日志与远程管理 |

### 5.2 Modbus 寄存器映射（主从契约）

| 寄存器 | 含义 | 类型 | 缩放 |
|---|---|---|---|
| 40001 | 温度 | int16 | ×10（0.1℃） |
| 40002 | 湿度 | uint16 | ×10（0.1%RH） |
| 40003 | 烟雾 | uint16 | ADC 原始值 |
| 40004~40005 | 电压 | uint32 | ×100（0.01V） |
| 40006~40007 | 电流 | uint32 | ×1000（0.001A） |
| 40008 | 状态字 | uint16 | bit0 故障 / bit1~5 越限 |

### 5.3 MQTT 接口

| 项 | 值 |
|---|---|
| Broker | mqtt.heclouds.com:1883 |
| 鉴权 | ClientID=设备名 / Username=产品ID / Password=设备密钥 |
| 属性上报 Topic | `$sys/{产品ID}/{设备名}/thing/property/post` |
| QoS | 1 |
| 报文格式 | OneNET 物模型 JSON |

## 7. 验收标准（冲刺版）

系统达到以下全部条件即视为验收通过：

1. STM32 节点通过 ModbusPoll 可读到 40001~40008 寄存器，数值正确
2. 网关通过 RS485 轮询读到节点数据，LVGL 屏幕实时显示
3. 网关通过 MQTT 将数据上报至 OneNET，平台可见数据曲线
4. 模拟断网，数据缓存至 SQLite；恢复网络后自动补传，OneNET 数据连续
5. 触发温度/烟雾告警，屏幕与云端均收到告警
6. 系统稳定运行 ≥ 2 小时无崩溃
